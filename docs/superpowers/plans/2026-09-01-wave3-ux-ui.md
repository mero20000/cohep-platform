# Wave 3 — UX/UI Improvements Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend form validation to all 9 forms, add server-side name redaction, fix Arabic locale inconsistencies, and verify reduced-motion support.

**Architecture:** Migrate all forms to the existing `validation.ts` + `useFormValidation` + `FormField` system. Add `?redactNames=true` query param to the student portal endpoint. Standardize locale codes to `ar-EG`/`en-GB`.

**Tech Stack:** Next.js 15, NestJS, Prisma, class-validator, motion/react, Tailwind CSS

## Global Constraints

- Bilingual messages: every validation message must have `{ en: string; ar: string }` shape
- Use existing rule builders from `@/lib/validation` — no new rules needed
- Use existing `FormField` component — do not create new field components
- Locale codes: `'ar-EG'` for Arabic, `'en-GB'` for English (date formatting)
- All forms must have `noValidate` on the `<form>` element
- All error messages must use `role="alert"` for accessibility

## Task 6: Hide Name Server-Side Redaction

**Files:**
- Modify: `backend/src/modules/students/student-portal.controller.ts`
- Modify: `frontend/src/app/student-portal/[code]/page.tsx`

**Interfaces:**
- Consumes: None (standalone)
- Produces: `?redactNames=true` query param support on portal endpoint

- [ ] **Step 1: Update backend controller**

Add `@Query` import and `redactNames` parameter:

```ts
import { Controller, Get, Param, Query } from '@nestjs/common'
// ... existing imports

@Get(':portalAccessKey')
@ApiOperation({ summary: 'Get student portal data by portal access key' })
async getPortal(
  @Param('portalAccessKey') portalAccessKey: string,
  @Query('redactNames') redactNames?: string,
) {
  const data = await this.studentsService.getPortalData(portalAccessKey)
  if (redactNames === 'true') {
    return { ...data, firstName: null, lastName: null, firstNameAr: null, lastNameAr: null }
  }
  return data
}
```

- [ ] **Step 2: Update frontend state**

Replace the `showName` useState with localStorage persistence:

```tsx
const [showName, setShowName] = useState(() => {
  if (typeof window === 'undefined') return true
  return localStorage.getItem('niangelos_hide_name') !== 'true'
})
```

Update the toggle to persist:

```tsx
const toggleName = () => {
  const next = !showName
  setShowName(next)
  localStorage.setItem('niangelos_hide_name', String(!next))
}
```

Update the toggle button `onClick` to use `toggleName`.

- [ ] **Step 3: Update fetch URL**

In the `useEffect` that fetches portal data, append the query param:

```tsx
const redactParam = !showName ? '?redactNames=true' : ''
const data = await portalGet<PortalData>(code, `/student-portal/${encodeURIComponent(code)}${redactParam}`)
```

Add `showName` to the dependency array of the useEffect.

- [ ] **Step 4: Remove client-side filtering**

Remove the `displayName` computation. Replace the `<h1>` render with:

```tsx
{student.firstName && (
  <h1 lang={lang} className="text-[1.75rem] leading-tight font-bold text-white truncate">
    {lang === 'ar' && student.firstNameAr
      ? `${student.firstNameAr} ${student.lastNameAr || ''}`.trim()
      : `${student.firstName} ${student.lastName}`}
  </h1>
)}
```

When `showName` is false and `redactNames=true`, the server returns `null` for name fields, so `student.firstName` is `null` and the `<h1>` won't render.
